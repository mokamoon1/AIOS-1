# 1. Purpose

This document defines the fundamental principles, rules, and constraints that govern the AIOS project.

All developers, AI agents, automated systems, and future extensions must follow these rules.

This document represents the highest-level authority after the project vision.

---

# 2. Core Principles

## 2.1 Capital Protection First

The primary objective of AIOS is not maximum profit.

The first priority is protecting investment capital through:

- Risk control.
- Diversification.
- Position management.
- Evidence-based decisions.

---

## 2.2 No Blind Decisions

AIOS must never make investment decisions based on:

- Random signals.
- Single indicators.
- Unverified information.
- Emotional assumptions.

Every decision must have supporting evidence.

---

## 2.3 Explainability Requirement

Every important decision must be explainable.

The system must record:

- Why an opportunity was selected.
- Which data was used.
- Which analysis methods contributed.
- What risks were identified.
- Why a decision was accepted or rejected.

---

# 3. Shariah Compliance Rules

## 3.1 Approved Universe

AIOS investment universe must only contain securities verified as Shariah compliant.

---

## 3.2 Shariah Data Sources

Shariah compliance information must come from approved external providers.

The system must not create its own independent religious classification.

---

## 3.3 Compliance Gate

No security may enter analysis, portfolio construction, or trading workflow before passing the Shariah compliance check.

# 4. AI Agent Rules

## 4.1 Agent Independence

Each AI agent must have:

- Defined responsibility.
- Clear inputs.
- Clear outputs.
- Limited authority.

---

## 4.2 No Agent Overreach

An agent cannot:

- Change system rules.
- Modify architecture.
- Bypass risk controls.
- Execute unauthorized actions.

---

## 4.3 Decision Collaboration

Important decisions should be produced through collaboration between specialized agents.

Examples:

- Market analysis agent.
- Risk agent.
- Portfolio agent.
- News agent.

---

# 5. Architecture Rules

## 5.1 Modular Design

The system must be built as independent modules.

Each component should be replaceable without rebuilding the entire system.

---

## 5.2 Communication Rules

Agents and modules should communicate through controlled interfaces.

Direct uncontrolled dependencies are prohibited.

---

## 5.3 Scalability

The architecture must allow future expansion:

- New markets.
- New brokers.
- New data providers.
- New AI agents.

---

# 6. Data Rules

## 6.1 Data Quality

The system must prioritize:

- Accuracy.
- Reliability.
- Traceability.

---

## 6.2 Data Sources

Every external data source must be documented.

Unknown or unreliable sources must not be used.

---

# 7. Development Rules

## 7.1 Documentation Before Code

Major features require documentation before implementation.

---

## 7.2 Testing Requirement

Every important module must include tests.

---

## 7.3 Version Control

Every significant change must:

- Have a Git commit.
- Have a clear description.
- Maintain project history.

---

# 8. Trading Rules

## 8.1 Paper Trading First

All strategies must be tested in simulation before real capital deployment.

---

## 8.2 Risk Assessment Required

No trade can be executed without:

- Risk evaluation.
- Position sizing.
- Portfolio impact analysis.

---

## 8.3 No Forced Trading

The system is allowed to decide:

"No action."

Not trading is an acceptable decision.

---

# 9. Change Management

Any change affecting:

- Architecture.
- Investment philosophy.
- Risk rules.
- Shariah workflow.

Requires review and approval.

---

# 10. Final Authority

The project owner has final authority over:

- Product direction.
- Feature approval.
- Strategic decisions.

Technical implementation follows the approved project rules.
